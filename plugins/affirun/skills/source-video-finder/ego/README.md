# Ego Lite (`browser=ego`)

Same procedure, different hands. Each helper builds one script and runs it with `ego-browser nodejs` (a fresh Node process; tabs and Page labels persist, variables do not).

**Use the helper scripts in `ego/` (this skill folder)** instead of writing each search and verify by hand, and do not read their source (their arguments are below); a batch of 20 reels averaged 13 minutes per reel with them. They are Node scripts, so the same command works on macOS, Windows and Linux, in bash, zsh, PowerShell or cmd: `node <this skill folder>/ego/<script>.mjs …`. Quote every argument that has spaces, and pass each id or image as its own argument. Each takes the TaskSpace id and works in Page `p1` (set the environment variable `EGO_PAGE=p2` for another). Redirect the output to a file when it is long (`> out.txt 2>&1`) and read it back. The result is the line that starts with `[` or `{`; lines starting `#` are notes, and `ego-browser` writes some lines of its own. All paths may be relative; the helpers make them absolute. If `ego-browser` is not on PATH, set `EGO_BROWSER` to its full path.

- Start: `start.mjs <space name> [profileId]` creates the run's TaskSpace and prints `{ "spaceId": <n> }`; pass that number to every other helper. The run folder, the reel and its frames come from `prep.mjs` in the skill folder (SKILL.md section 1), which needs no browser.
- Search: `tt-search.mjs "<q>" <space> <out.png>` (starts from the TikTok home page every time and prints `# searched: ?q=…`: check it matches, a second search typed on a results page used to return the previous results), `dy-search.mjs` (drops photo posts, returns `secUid`; `node ego/fmt.js < out.json` prints the JSON as a table), `rn-search.mjs` (writes `<out.png>.json` with ids and tokens), `ig-search.mjs`, `cp-search.mjs` (Coupang; each row's `img` is the card photo as a 492 px `coupangcdn.com` address, pass it as the listing's `imageUrl`), `1688-img.mjs <space> <image> <out.png>`, `lens.mjs <space> <out dir> <image>...` (Google Lens on all images at once, one Page each: prints a JSON array of `{ image, overview, videos, all, exact }`, video links first, as host, path-trimmed url and text, and saves `<name>-all.png` and `<name>-exact.png` in the out dir).
- Grids: `tt-grid.mjs <handle> <space> <out.png> [scrolls=2]` (prints one JSON object, `{ n, out, body }`, not an array; about 45 videos per scroll; to read a big grid fast, take each card's cover `img.src` in `page.evaluate`, fetch them, and lay them out as one labelled montage), `dy-grid.mjs <space> <secUid> <out.png>`, `ig-grid.mjs <handle> <space> <out.png>`.
- Verify: `tt-click-verify.mjs "<query that shows the leads>" <space> <dir> <id>…` (opens each video by clicking its card, stops with `error: "captcha"`), `tt-grid-verify.mjs <space> <dir> <id>…` (cards on the grid already open), `dy-verify.mjs <space> <dir> <awemeId>…`, `rn-verify.mjs <space> <dir> <out.png>.json <noteId>…`, `ig-verify.mjs <space> <dir> <code>…` (returns the owner). All save 30% and 70% screenshots into `<dir>`, then lay them out and print `# sheet: <file> | columns left to right: <ids> | top row 30%, bottom row 70%` (six leads per sheet; a lead whose screenshots are missing is left out): Read the sheet, not the screenshots.
- Session page: `session-wait.mjs <space> "<session url>" [max seconds=180]` opens the saved session, waits for the downloader, presses `다시 받기` once on failed cards and prints one JSON line (`result`, `counts`, a line per card with its quality or error). One call, with a shell timeout longer than the wait; `report.md` step 3 says how to read `result`.
- `sheet.mjs <tt|dy|rn|ig|raw> <out.jpg> <shot>…` makes a sheet by hand, for what the verify helpers' own sheet does not fit: it crops the video area out of the screenshots you name (scaled to the shot size) with `ffmpeg` and lays them side by side in argument order. Douyin landscape videos need `raw`.
- Video size: `w`/`h` can read 0 before metadata loads; do not take 0 to mean unplayable.

- **One TaskSpace per run**, named after the reel code and created with the saved profile by `start.mjs` (the profile applies only at creation); work in Page `p1` and open a second Page only to keep the search results while a video is open. Close with `task.finish({ keep: [] })` at the very end, after the session page has fetched its videos (`report.md` step 3 runs in Ego Lite too: install the downloader extension there).
- **Search** still goes through the site's own search box: click it, type the query, press Enter, then wait for the result cards. Do it, the extraction and a screenshot in the same script. TikTok: `page.click('[data-e2e="nav-search"]')`, the sidebar search button (its accessible name follows the UI language, `Search` or `검색`, so a name locator fails on a Korean UI; the `input[data-e2e="search-user-input"]` under it has a zero-size box and refuses clicks). Douyin: `input[placeholder*="搜索你感兴趣的内容"]`, wait for `.search-result-card`, Escape. RedNote: `#search-input`, wait for `section.note-item`, then `text=Videos`.
- **Extraction** is the same in-page code as in `sites.md`, inside `page.evaluate()`. Nothing is filtered, so return full links (RedNote with its `xsec_token`) and cover `src` addresses directly.
- **Covers:** take `page.screenshot({ path })` of the grid and Read it, as before. Paths given to `ego-browser` must be absolute.
- **Verify** a lead with one script: `goto()` the video page (a direct TikTok `/@handle/video/<id>` address works for the first one or two, then TikTok throttles them: see `sites.md`), wait until `video.duration > 0`, pause and seek the `<video>` to 30% and 70% and return its `getBoundingClientRect()`, `screenshot({ path })` after each seek, then crop the video area with `ffmpeg -i <shot> -vf crop=W:H:X:Y <out>` (the screenshot is in CSS pixels; on Douyin take the centred 9:16 part of the wide player rect). Three leads per script is fine. Douyin served 1080x1920 here where Chrome got 720x1280 for the same video.
- **Login wall, CAPTCHA or slider:** `await task.handOff()`, end the round, tell the user what to do in the Ego Lite window, and resume with `takeOverTaskSpace(<id>)` when they say so. Never solve it.
- Scripts run by `ego-browser nodejs` get no environment variables (`process.env` is empty): write values into the script. Douyin's home page can miss its `load` event for 30 s; catch the `goto` timeout and wait for the search box instead.
- RedNote profile grids are virtualized: cards above the viewport are removed, so collect note ids while scrolling in small steps (900 px) instead of once at the end. On a note page the first `/user/profile/` link is the signed-in user ("Me"); the author's is the one whose text is the author name. Grid card links are `/user/profile/<uid>/<noteId>?xsec_token=…`: the note id is the last 24-hex part, not the first.
- **Its own sign-ins.** Ego Lite is a separate browser profile: check TikTok, Douyin, RedNote (and Instagram when the run needs it) once at the start. The Affirun app must be signed in there **as the same account the MCP uses**: open the app and check it does not land on `/login`, and that the session `url` shows the session (a different account sees no session and lands on `/dashboard`). If it is signed out or another account, `handOff()` and ask the user to sign in in the Ego Lite window. Never type a password. A card can fail with `Content script READY 타임아웃`; see `report.md` step 3.
- **Several runs at once** share one Ego Lite and its downloader: four in parallel worked with no Douyin or RedNote walls; five brought two TikTok CAPTCHAs. Each run keeps its own TaskSpace and never touches another's.
