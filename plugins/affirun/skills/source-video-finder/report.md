# Report: save the session, fetch the videos, reply

Read this when the searching and verifying are done (section 4 of `SKILL.md`). Sections named here (0 to 3.5) are in `SKILL.md`.

1. Fill `summary` in `run.json` (one Korean line: the product, how many usable videos, where from; with several targets, one clause per target, found or not) and a short Korean `label` for the product. Give every target a Korean `note`: where it was found, or for one with no video, what you tried ("틱톡 3번, 더우인 2번, 레드노트 2번 검색, 명함·이름표 제작 영상만 나옴").
2. **Save it to the app** with the affirun MCP `save_source_finds`: `mediaId` (the reel code, the same for an external reel), `label`, `summary`, `mode`, `targets` (every target, **including the ones you found nothing for**: `label`, `note`), `candidates` (every verified video, same and similar: `platform`, `url`, `account`, `tier`, `match` (`same` or `similar`), `target` (index into `targets`), `sameShoot`, `lengthSec`, `note`, `copies`), `near` (only what was not usable), `excluded`, `searches` (each with its `target`), `blocked`, and `coupang` from section 3.5. The page groups the videos by target and shows a target without videos as not found.
   - **Re-running a session** (the user gives a session link, `.../source-finds/<id>`, and asks to search again or harder): pass that id as `sessionId`. The save replaces the session's results instead of making a new one; videos already fetched (same platform and video id) keep their copy, and a video left out of the new list is removed, so send every video you still want, old ones included. Start from what the session already holds (its searches, `near`, `blocked`): do not repeat a search that found nothing, and open the old `near` links first.
   - `agentUsage`: run `node <this skill folder>/usage.mjs --since <startedAt> --browser <chrome|devtools|ego> --reel <code>` right before the save (`--reel` makes it count the subagent's own transcript when the run is one) and pass its usage fields (`model`, `browser`, `calls`, `inputTokens`, `cacheReadTokens`, `cacheWriteTokens`, `outputTokens`, `durationSec`) as `agentUsage`. It counts this run's model calls and tokens from the Claude Code transcript (`CLAUDE_CODE_SESSION_ID`) or Antigravity transcript (`ANTIGRAVITY_CONVERSATION_ID`); in any other agent skip it and save without `agentUsage`. It is stored for cost tracking only: the app never shows it, so do not mention it in the reply either unless asked. If the script fails, or reports implausibly few calls (under 5), save without it: never pass a value you doubt.
   - `coupang` is one item per product: `label`, `outcome` (`number` 번호로 찾음, `link_page` 링크 페이지에서 찾음, `block_only` 블록만 찾음, `coupang` 쿠팡 후보, `number_model_differs`, `number_wrong`, `sold_elsewhere`, `not_found`), `captionNumber`, `blockTitle`, `product` (what the account links: `name`, `price`, `url` = the clean `productUrl`, `option`, `delivery` `rocket`/`seller_rocket`/`none`, `reviews`), `otherUrl` (a block that leads off Coupang), `alternatives`, `candidates` (the Coupang list, closest first, each with `grade` `same`/`model`/`similar`, `differs`, `opened`), `queries`, `note`, `notChecked`. The server refuses an affiliate short link (`link.coupang.com/a/...`): send the clean address.
   - Pictures: set `uploadImage: true` on each listing you have a picture for, or `imageUrl` for a `thumbnail*.coupangcdn.com` address you read from the page. The response lists `imageUploads` (`slot` like `0.candidate.1`, `uploadUrl`); PUT each file: `curl -sf -X PUT -H 'Content-Type: image/jpeg' --data-binary @cand-1.jpg "<uploadUrl>"` (15 minutes).
   - Found no footage but a product? Save with `candidates: []` and the `coupang` items; the session shows the product alone. If the Coupang part finished after you saved, call `save_coupang_products` with the returned `sessionId` instead of saving again. Only videos you opened go in `candidates`. It returns the session's `url` (벤치마킹 > 원본 찾기), where the user plays the videos and starts a scenario from the ones they pick. Frames are not uploaded; the page plays the videos instead.
3. **Open the session `url` in the tab you have been using.** The page hands the videos to the user's downloader extension (Instagram reels are fetched by the server and need no extension), which opens each video page in a background tab, takes the best stream and uploads it (10–20 s per video; tabs flash open and closed, which is expected). Wait until no card says `받는 중` or `받을 차례` (cap 3 minutes; with more than 10 videos, 5 minutes): in Ego Lite with `ego/session-wait.mjs` (below), in Chrome by reading the page text every 15–20 s. Each fetched card shows its quality as `고화질 1080p`, `보통 720p` or `저화질 <n>p`: note it per video for the reply. If the page says the downloader is missing or outdated (`다운로더 설치` / `다운로더 업데이트`), tell the user (the last part of this file says how an outdated one is fixed); the session is saved either way and the videos fetch the next time they open it. If the app is signed out (the page redirects to `/login`), a batch sub-agent does not type a password and reports the `url`. Note which cards say `영상을 받지 못했어요` and why.
   - **`Content script READY 타임아웃` is common on TikTok too** (2026-11-19: about one TikTok card in three on the first pass, all six on one run). After the queue drains, press `다시 받기` once on every card that shows it (`session-wait.mjs` does); that fixed all but 2 of about 35 in the batch.
   - Count states per card, not over the page text: the page has static text that matches `받는 중`, and a card's quality line sits next to the following card's note. Walk up from each video link to the ancestor that holds exactly one platform link and read that.
   - Quality the app shows is what was fetched, not what the source has: Instagram reels come in at 720p even when they play at 1080x1920, and Douyin 4K or 1440p sources often come in at 720p. Say so when you rank copies across platforms (a TikTok copy at 1080p beats the Instagram original at 720p for a remake).
   - **Ego Lite: wait with one command**, `node <this skill folder>/ego/session-wait.mjs <space> "<session url>" [max seconds=180]` (300 with more than 10 videos, or with several runs sharing the downloader). It opens the page, waits by itself, presses `다시 받기` once on every failed card, and prints one JSON line: `result`, `counts`, and one line per card (platform, video id, state, quality or error). Give the shell call a timeout longer than the wait (Claude Code: `timeout` of the seconds plus 30, in milliseconds), or it is moved to the background and its output arrives late. **Run it once and report what it says; do not poll again and do not write your own loop**: every extra call at this point re-reads the whole run. `result` is `done` (nothing left to fetch), `timed_out` or `stalled` (some still `pending` or `fetching`: say how many; they fetch when the user opens the session), `not_started` (30 seconds and the downloader took none: the downloader in this browser is not fetching for this app, most often a build that talks to another server, or the extension is disabled; say so and stop), `downloader_missing` / `downloader_outdated`, or `signed_out`.
4. If saving fails for another reason than `payment_required`, fall back to the HTML page: `node <this skill folder>/report.mjs ./.source-finder/<code>/run.json ./.source-finder/<code>/report.html` (images inlined, about 2 MB for 8 candidates) and send it with `SendUserFile` (`display: "render"`) when that tool exists; otherwise give the user the file path.
5. In chat, reply in Korean with a short version: the product and its Coupang result (in the coupang-product-finder report words: how it was found, the clean address, or the candidate count and the closest grade), the top 3 videos (same-shoot first) with tier, **quality** (`1080p` etc.) and link (with several targets: the best one or two per target, and plainly which targets have none), how many same and how many similar videos, how many of them are 1080p, how many searches, anything that blocked you, how many videos are playable in the app, and the session link from step 2.

Close the tab you opened once the videos are in (closing it earlier does not stop the extension).

## An outdated downloader

**An outdated downloader is not a run failure.** When the installed extension is older than the app's build (it answers `unknown_message`), the session page says `다운로더 업데이트` and the videos stay `받을 차례` (seen on every run, 2026-11-19). The session is saved; the videos fetch after the extension is reloaded from `apps/downloader/.output/chrome-mv3` and the session page is opened again. Report it and go on.
