# Site notes

How each site is driven: selectors, clicks, waits, capture. With `browser=chrome` or `browser=devtools` read this before the first browser step. With `browser=ego` the helpers in `ego/` already do what is written here: read a site's note only when its helper fails or you write a script of your own. Sections named here are in `SKILL.md`.

## Capturing frames (section 3)

- TikTok and Douyin both use a plain `<video>`: pause it, set `currentTime` to about 30% and 70% of `duration`, wait 1.2–1.5 s, and capture **with `save_to_disk: true`** so the frame lands on disk for the report.
- **The zoom region depends on the window, so derive it every time.** Take a screenshot first, read the `<video>` element's `getBoundingClientRect()`, and zoom on that rect (Douyin letterboxes the video in a wide player: use the centred 9:16 part of it). Fixed numbers did not fit in 6 of 11 runs (2026-11-19). Working regions seen: TikTok `[272, 10, 794, 940]` in a 1274-wide frame, `[0, 100, 545, 1070]` and `[254, 288, 590, 886]` in other window sizes; Douyin `[292, 65, 512, 456]` and `[256, 66, 624, 522]` in the wide player. Treat them as examples only.
- A Douyin video page takes about 7 seconds before `video.duration` is finite: wait for it before seeking.
- Batch two candidates per `browser_batch` call and keep the zoom steps in small batches: one failed item drops the zoom images of its whole batch. Inside `browser_batch` a screenshot is the `computer` tool with `action: "screenshot"`.

## Sites

- **Google Lens** (`google.com`): open `https://www.google.com/?hl=en` and click the `Search by image` button. Put the frame on the panel's hidden file input, not the `upload a file` button (that opens a native picker). In Ego Lite run `node ego/lens.mjs <space> <out dir> <image>...` with all the frames: it opens one Page per image and runs them together. In Chrome, open one tab per frame and do it in two `browser_batch` calls (tested 2026-11-19 with two tabs): first, for every tab, `navigate`, a `javascript_tool` click on `[aria-label="Search by image"]`, and `find` "file input for image upload" (the hidden `file-input`, not the button); then `file_upload` into every tab, one `wait` of 7 seconds, and the link reading below in every tab. Results load at `/search` in about 5 seconds. Scroll three screens, then collect the result links as hostname and pathname only (Chrome blocks query strings), skipping Google's own hosts; sort out the video links (`tiktok.com/@<handle>/video/<id>`, `instagram.com/reel/` or `/p/`, `facebook.com/.../videos/`, `youtube.com/shorts/`) first. Then click `Exact matches` for the pages that carry this very image. One upload per target did not bring Google's "unusual traffic" page in testing; if it shows, do not solve it: skip Lens for the run and say so.
- **TikTok** (`tiktok.com`): click the search box in the left sidebar (`[data-e2e="nav-search"]`; its label is `Search` or `검색` depending on the UI language, so find it by that attribute, not by name), `cmd+a`, type, Return. After the first search the search box moves, so find it again before clicking it. Results link to `/@handle/video/<id>`: collect with `[...document.querySelectorAll('a[href*="/video/"]')]` and `/@([^/]+)\/video\/(\d+)/`, card text from the nearest parent with text. If the page says "Something went wrong", reload once. A "Please wait" or error page on first load usually clears when you open `https://www.tiktok.com/explore` or reload once: try that before calling the platform blocked (runs 2–9, 2026-11-19). Opening a `/@handle/video/<id>` address directly can land on a browser error page (2026-11-18, twice in a row; run 5, 2026-11-19) and sometimes works (run 11): open the video by clicking its card in the search results or the account grid first, and use the direct address as the fallback. When you download frames or videos with `curl`, pass `-L`: without it you save a 100-byte redirect file (run 10). Results follow the user's region: Korean LIVE streams can fill the top (skip the LIVE block) and Korean re-uploads appear (exclude them).
- **Douyin** (`douyin.com`, search box `搜索你感兴趣的内容`): result cards are `.search-result-card`. The data sits on the React fiber of the card's `<img>`: walk `__reactFiber*` `.return` up to ~40 levels until a `memoizedProps` value has `awemeId`; it also has `desc`, `authorInfo.nickname`, `authorInfo.secUid`, `isAds`. Video link: `https://www.douyin.com/video/<awemeId>`. Skip `isAds`. Press Escape and blur the search box after searching; the suggestion dropdown can still cover the top of the grid in the screenshot. `awemeType` 68 is a photo post (图文): drop it; for some queries (`不锈钢剥虾器`) the first screen is mostly photo posts and the seller clips sit at ranks 20 to 29.
- **RedNote** (`rednote.com`): cards are `section.note-item` (`a.cover` href has the note id and `xsec_token`, `.title`, `.author .name`). The All tab mixes photo posts and videos, and a photo post can look exactly like the product (2026-11-18: mirror-silver menus were almost all photos); a note is a video only if its page has a `<video>`. A photo post goes in `near` with "사진 게시물", never in `candidates`. Its description often gives the Chinese trade name to search next (镜面银卡 压凹). After searching, click the Videos / 视频 tab. Note links need their `xsec_token`; return the note id and the token as separate plain strings and build `https://www.rednote.com/explore/<id>?xsec_token=<token>` yourself, with a script from the saved search JSON, never by hand (a run saved four links with a typed placeholder token and the server took them). Covers are often designed text cards, so open a note when the cover is unclear. A RedNote `<video>` that never played shows only its poster after a seek: play it muted for a moment before each capture, or a moving video looks static.
- **Instagram** (`instagram.com`): keyword search is `https://www.instagram.com/explore/search/keyword/?q=<words>` (a constructed link is fine here). Use **two words** (three at most): `mirror menu` found the maker, `mirror foil menu` returned "No results". Instagram also returns "No results" for slang or sensitive words (`humping dog charger`, while `dog charger` held all four same-shoot videos): drop such a word before calling Instagram empty. Results are a grid of `a[href*="/p/"], a[href*="/reel/"]` (the search grid links reels as `/p/<code>`); the reel being searched for shows up too, skip it. Open a lead at `https://www.instagram.com/reel/<code>/` (a plain `<video>`; seek and capture as in section 3; `[220, 10, 830, 1080]` was a working zoom, derive yours from the `<video>` rect). The reel page is a feed: the owner is the first `a[href$="/reels/"]` link with text, not the first profile link (that is the signed-in user). Then **sweep the account**: `https://www.instagram.com/<handle>/reels/`, scroll three or four screens (nine for an older source); a maker's other reels hold the reel's other scenes. Save with `platform: "instagram"` and the `/reel/<code>/` link; the server fetches these itself (no downloader tab), a few seconds each. Never like, follow or message from the user's account.
- **TikTok Shop videos cannot be had on the web.** Many seller and affiliate videos (product-tagged, common for Thai and Vietnamese shops) show "View TikTok Shop videos in the TikTok app" over a blank player, and the page data has no `playAddr`, so neither verification nor the downloader works. Check for that text right after opening, put the video in `near` with "틱톡샵 영상, 웹 재생 불가" and what the cover shows, and do not count it or spend more time on it. The user can open it in the TikTok app.
- **TikTok throttles direct video loads.** After one or two `/@handle/video/<id>` loads in a row (Ego Lite too, 2026-11-19), the next ones fail with `ERR_HTTP_RESPONSE_CODE_FAILURE` and in-page `fetch` of video pages returns no data. Open videos by clicking their card in a search grid (it opens the player over the grid; Escape closes it).
- **The Claude in Chrome extension (`browser=chrome` only) refuses any JavaScript result containing a URL with a query string or cookie-like data** (`[BLOCKED: Cookie/query string data]`). Return ids and text only, never `location.search`, `img.src` or full hrefs with `?`. Cover images are therefore judged from screenshots.
